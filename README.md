# Codable Resume

A **code-first resume** written in [Typst](https://typst.app). Edit content in `resume.typ`, run a single command, and export to PDF. No GUI required—everything is versionable and scriptable.

## Project overview

- **Input:** `resume.typ` — one Typst source file with your name, contact, experience, education, skills, and optional projects.
- **Output:** `resume.pdf` — generated by the Typst compiler.
- **Workflow:** Edit variables and arrays in code → run build → open PDF. Use watch mode for live recompilation while editing.
- **Learning Typst:** See the [**docs/**](docs/README.md) folder for short guides on Typst syntax, editing this resume, and styling/layout—useful for anyone using this project in the future.

## Requirements

- **Typst CLI** (the only required dependency; no Node.js needed for compilation, but npm scripts are provided for convenience).

## Installation

### 1. Install Typst

Install the Typst compiler using one of the following methods.

**macOS (Homebrew):**
```bash
brew install typst
```

**Windows (scoop):**
```bash
scoop install typst
```

**Linux (typical):**
- Download a release from [Typst releases](https://github.com/typst/typst/releases) and put the binary in your `PATH`, or
- Build from source: `cargo install typst-cli` (requires [Rust](https://rustup.rs)).

**Verify installation:**
```bash
typst --version
```
You should see a version number (e.g. `typst 0.11.0`).

### 2. Clone or copy this project

If this is already in your `~/CodeBase` folder, you’re set. Otherwise:

```bash
cd ~/CodeBase
# If you have it in git:
# git clone <your-repo-url> codable-resume
cd codable-resume
```

### 3. (Optional) Use npm scripts

This project includes a `package.json` with `build` and `watch` scripts. You don’t need to run `npm install`—there are no npm dependencies. The scripts simply call the Typst CLI. If you prefer not to use npm, use the Typst commands directly (see “Usage” below).

## Usage

### Build PDF (one-off)

From the project root (`~/CodeBase/codable-resume`):

```bash
npm run build
```

Or without npm:

```bash
typst compile resume.typ resume.pdf
```

Output: `resume.pdf` in the same directory. Open it with any PDF viewer.

### Watch mode (recompile on save)

While editing `resume.typ`, run:

```bash
npm run watch
```

Or:

```bash
typst watch resume.typ resume.pdf
```

Save the file and the PDF will recompile automatically. Stop with `Ctrl+C` when done.

### What to edit in `resume.typ`

All content is defined at the top of `resume.typ`. Edit these and leave the “Resume body” section as-is unless you want layout changes.

| Section      | Variables / structure |
|-------------|------------------------|
| **Header**  | `name`, `tagline`, `email`, `phone`, `website`, `location` |
| **Experience** | `experience` — array of `(title, company, dates, bullets)` |
| **Education**  | `education` — array of `(degree, institution, dates, note?)` |
| **Skills**     | `skills-heading`, `skills-languages`, `skills-tools` (or customize `skills-content`) |
| **Projects**   | `projects` — array of `(name, link, description)`; use `()` to hide the section |

- Add/remove list items by editing the arrays.
- Dates and bullets are plain strings; format them however you like (e.g. `"Jan 2022 – Present"`).

## Customization

- **Paper size:** In `resume.typ`, change `#set page(paper: "us-letter", ...)` to e.g. `paper: "a4"`.
- **Fonts:** Change `#set text(font: "Linux Libertine", ...)` to another font name if you have it installed or available to Typst.
- **Layout / styling:** Adjust the `#set page(...)`, `#set text(...)`, and `#show heading.where(...)` blocks; the “Resume body” section controls structure and can be modified for different layouts.

## Troubleshooting

- **`typst: command not found`** — Typst is not in your `PATH`. Install it using one of the methods above and ensure the binary is on `PATH`.
- **Compilation errors** — Read the error message; Typst usually points to the line. Check brackets, commas in arrays, and that strings are in double quotes.
- **Missing font** — If you see font-related errors, switch to a built-in font like `"Linux Libertine"` or remove the `font` argument to use the default.
